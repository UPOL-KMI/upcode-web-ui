### X-001 — GitHub Classroom import

**Why.** GitHub Classroom is being retired, and the courses that used it have assignment templates
with automated tests already written. Those courses need somewhere to go, and re-typing every
exercise by hand is the thing that stops people moving. The operator has such templates.

**What maps cleanly.** Classroom's `autograding.json` describes tests as `{name, setup, run, input,
output, comparison, timeout, points}`. The `input`/`output` kind -- feed this to stdin, expect that
on stdout, compare `exact` or `included` -- is **exactly** what a ReCodEx test with the diff judge
is; the seeded `[seed] Echo Greeting` exercise is that shape. Alongside it, the template repo's
`README.md` is the exercise text, and its other files are supplementary files. For an intro
programming course, which is most of the affected population, that covers the bulk of an assignment.

**What does not map, and must be said rather than silently dropped.**

- A `run` command that is an arbitrary shell line has no equivalent: ReCodEx's pipelines are
  declarative (a compilation pipeline and an execution pipeline per environment), not "run this".
- Tests that invoke a framework (pytest, JUnit) inside the repo cannot become per-test
  stdin/stdout pairs. They can become **one** test judged on the exit code -- ReCodEx has
  success-exit-code configuration -- but that collapses twenty test cases into one pass/fail, which
  the importer must state rather than pretend.
- Per-test `points` map onto the score configuration T-025 built, but Classroom's totals and
  ReCodEx's are not the same arithmetic.
- **A reference solution cannot be imported.** T-011 established that core-api refuses to let an
  exercise be assigned without one, and Classroom templates rarely carry a solution. So an import
  lands an exercise that is deliberately **not yet assignable**, and the screen has to say why.

**Shape this suggests.** Not one-click. An import produces a **draft exercise** the author then
finishes -- reference solution, limits, environment -- plus a **report of what could not be
mapped**, test by test. That is more honest than a wizard that appears to succeed and produces an
exercise that grades nothing.

**The good news for this repo.** It needs **no API change** (constraint 1). Everything an import
would do -- create an exercise, write its texts, upload supplementary files, write the test
configuration and the score config -- is what T-008, T-009, T-023 and T-025 already do through
existing endpoints. An importer is a file parser plus the calls those screens already make.

**Open questions before building.** Which Classroom export actually exists once the service is
retired (the roster and template are a git repo and a JSON file, but is there a bulk export?);
whether to import a **roster** into a group as well, which needs email addresses Classroom may not
carry; and whether the newer GitHub-Actions-based autograding is worth parsing at all, since it is
arbitrary YAML running arbitrary steps.
